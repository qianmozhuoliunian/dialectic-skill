# 技术方案：本地笔记搜索

类型：人为编写的教学示例，输入与证据均为虚构，非真实性能测量。

## 输入

> 我做个人本地笔记搜索，不上传笔记。希望常用查询在两秒内有结果。
> 已有标题检索。新方案把 README 改为“所有查询都在两秒内完成”，但没有计时数据。
> 为了方便，有人建议把全部笔记上传云端。
> 请优化，不要扩成多人服务。

## 目标与批评

B1：本人本地使用、不上传笔记；常用查询两秒是待验收目标，不能扩大为所有查询保证。保留已存在的标题检索，不假设它的速度已知。

| ID | 裁决 | 验收与状态 |
| --- | --- | --- |
| C1：性能声明超出证据 | 接受。README 文案不是计时数据 | 删除“所有查询”保证，说明常用查询两秒是目标；文案可 verified，实际速度 needs-evidence |
| C2：云端上传违反约束 | 接受这个违规判断，拒绝上传建议 | P2 保留本地存储和处理；这里只验证方案文字，未检查真实网络行为 |

为避免一个编号同时声称“性能通过”和“性能未通过”，C1 的验收主体保留为性能目标：状态 needs-evidence；删除夸大措辞只是已完成的子项。

## 最小修订

P2：沿用本地标题检索。先选十条常用查询，在说明的设备与笔记规模下逐条计时，报告各次结果及冷启动/热运行条件。发现超过两秒的查询后，针对该瓶颈优化；不要未经测量先切换整套技术。

README 写：“个人本地笔记搜索；常用查询两秒内返回是当前目标，尚待测量。”不宣称已经执行计时，也不声称没有任何联网行为已获验证。

## 输出

最终建议是可执行的测量计划，尚不能保证速度达标。下一步运行十条事先选定查询；验收这些查询在记录条件下是否均不超过两秒，并保留原始时间数据。有限样本不能证明所有输入都满足目标。

使用 1 轮；停止原因 needs-evidence。没有增加并发、账号系统或云端上传。
